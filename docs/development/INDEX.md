# Development Documentation

This category defines how contributors build, test, review, release, and
maintain Tracekeeper.

## Belongs Here

- Repository setup, validation, pull requests, packaging, release, and documentation rules
- Focused security-review triggers and contributor verification requirements

## Does Not Belong Here

- Product behavior, architecture topology, technology rationale, or current progress
- Implementation plans, handoffs, research notes, and dated acceptance evidence

## Current Documents

- [ENGINEERING_AND_RELEASE.md](ENGINEERING_AND_RELEASE.md) — Repository workflow, validation, packaging, release, and documentation standards.
- [SECURITY_REVIEW.md](SECURITY_REVIEW.md) — Changes that require focused security review and the evidence expected.
